2. CubeMX 생성 코드의 흐름

이번 프로젝트는 main.c가 애플리케이션 초기화 흐름을 담당하고, HAL 초기화 과정에서 MSP 함수가 호출되어 실제 GPIO와 주변장치 클럭을 연결한다.

main()→HAL_Init()→SystemClock_Config()→MX_GPIO_Init()→MX_I2C1_Init()→MX_SPI2_Init()→MX_USART1_UART_Init()

각 HAL_xxx_Init() 함수는 해당 핸들의 Instance와 Init 설정을 사용한다. HAL 초기화 중 HAL_xxx_MspInit()이 호출되어 GPIO Alternate Function 및 주변장치 클럭을 설정한다.

6. Base Address와 Register Offset 읽는 법

주변장치의 Base Address는 해당 주변장치 레지스터 영역의 시작 주소다. 각 레지스터는 Base Address에서 일정한 Offset만큼 떨어져 있다.

Register Address = Peripheral Base Address + Register Offset

예: USART1 BRR
Base Address = 0x40011000
BRR Offset   = 0x00000008
Register     = 0x40011008
주변장치Base Address버스선택 이유
USART10x40011000APB2main.c의 huart1.Instance=USART1
SPI20x40003800APB1main.c의 hspi2.Instance=SPI2
I2C10x40005400APB1main.c의 hi2c1.Instance=I2C1

RM0390의 Memory Map / peripheral boundary address 표에서 Base Address를 찾고, 각 통신 장의 Register Map에서 Offset을 확인한다.

핵심 차이 요약

  • UART: 별도 Clock 선 없이 양쪽 장치가 같은 Baud Rate를 사용해 비동기 직렬 데이터를 주고받는다.
  • SPI: Master가 SCK를 생성하고 MOSI/MISO로 데이터를 교환한다. Full-Duplex 통신이 가능하다.
  • I2C: SDA/SCL 두 선을 여러 장치가 공유하고, 주소와 ACK/NACK 절차를 통해 대상을 구분한다.

8. 프로젝트에서 발견한 주의점

① USART1과 USART2 핀 설정이 모두 보임 — 오류로 단정하지 말 것

main.c의 MX_GPIO_Init()는 PA2/PA3를 GPIO_AF7_USART2로 설정한다. 이는 NUCLEO-F446RE 보드의 ST-LINK Virtual COM Port 경로와 연관된 보드 공통 설정이다.

실제 사용자 통신 주변장치 초기화는 MX_USART1_UART_Init()이며, stm32f4xx_hal_msp.c에서 PA9/PA10을 GPIO_AF7_USART1로 설정한다. 따라서 과제의 UART 분석 대상은 USART1(PA9/PA10)이다.

② SPI2 NSS 핀이 별도로 할당되지 않음

SPI_NSS_SOFT로 설정되어 있어 하드웨어 NSS 핀을 자동 제어하는 구성이 아니다. 실제 외부 Slave를 선택하려면 별도 GPIO를 Chip Select로 제어하는 방식이 필요하지만, 현재 코드는 통신 동작을 구현하지 않는다.

③ SPI2의 PC1 MOSI AF7은 데이터시트와 일치

STM32F446 데이터시트 Table 11에서 PC1의 SPI2_MOSI는 AF7, PC2의 SPI2_MISO는 AF5로 표기된다. 따라서 MSP 파일의 PC1 AF7 설정은 유효한 핀 매핑이다. PC3도 SPI2_MOSI 대체 핀으로 제시되지만, 이번 프로젝트는 PC1을 선택했다.

④ I2C GPIO Pull 설정

PB6/PB7은 Open-Drain 및 GPIO_NOPULL로 설정됐다. I2C 버스에는 Pull-up이 필요하므로 실제 보드/외부 회로에 Pull-up 경로가 있는지 확인해야 한다. 소스 코드만으로 보드의 저항 연결 상태를 단정하지 않는다.

⑤ 통신 API는 아직 없음

현재 코드는 초기화만 한다. HAL_UART_Transmit(), HAL_SPI_TransmitReceive(), HAL_I2C_Master_Transmit() 같은 데이터 송수신 호출이 확인되지 않는다. 따라서 보고서에는 “CubeMX 통신 주변장치 설정 및 핀/레지스터 분석”으로 기술하고, “통신 테스트 완료”라고 쓰지 않는다.
