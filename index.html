3. 파일끼리 어떻게 연결되는가?

3-1. 헤더(.h)와 소스(.c)의 관계

usart.h는 USART 핸들과 초기화 함수가 다른 파일에서도 보이도록 선언한다.

/* usart.h */
extern UART_HandleTypeDef huart1;
void MX_USART1_UART_Init(void);

/* main.c */
#include "usart.h"

/* main() */
MX_USART1_UART_Init();

usart.c는 위 선언의 실제 정의를 가진다.

/* usart.c */
UART_HandleTypeDef huart1;

void MX_USART1_UART_Init(void)
{
    huart1.Instance = USART1;
    /* Init parameter assignments ... */
    HAL_UART_Init(&huart1);
}
문법의미
extern변수의 실체는 다른 C 파일에 있고, 이 파일에서는 외부 변수로 사용한다고 선언
함수 원형 선언함수 이름, 반환형, 매개변수를 컴파일러에 알림
#include헤더 선언을 현재 C 파일에 포함
HAL_UART_Init()HAL 라이브러리의 초기화 구현으로 이동해 설정을 하드웨어에 적용

3-2. 실제 호출 흐름

main.c→usart.h→MX_USART1_UART_Init()→HAL_UART_Init()
HAL_UART_Init()→HAL_UART_MspInit()→GPIO + RCC 설정
HAL_UART_Init()→UART_SetConfig()→USART CR1/CR2/CR3/BRR

SPI와 I2C도 같은 큰 구조를 가진다. 각 HAL Init 함수가 MSP 초기화 함수를 불러 GPIO와 주변장치 클럭을 준비하고, 이어서 주변장치 설정 레지스터를 구성한다.

3-3. 이 프로젝트에서 MSP 코드 위치

중요한 구조 차이
이번 ZIP에서는 통신별 HAL_UART_MspInit(), HAL_SPI_MspInit(), HAL_I2C_MspInit()가 전부 stm32f4xx_hal_msp.c에 모여 있지 않다. 각 함수가 각각 usart.c, spi.c, i2c.c 안에 생성되어 있다. stm32f4xx_hal_msp.c에는 HAL_MspInit() 전역 초기화가 있다.

4. 메모리 주소와 레지스터에 접근하는 원리

4-1. Base Address + Offset

주변장치는 메모리 맵에 연결되어 있다. 주변장치의 시작 주소(Base Address)에 레지스터별 Offset을 더하면 해당 레지스터의 주소가 된다.

Register Address = Peripheral Base Address + Register Offset

USART1 BRR = 0x40011000 + 0x08 = 0x40011008
SPI2   CR1 = 0x40003800 + 0x00 = 0x40003800
I2C1   CCR = 0x40005400 + 0x1C = 0x4000541C

4-2. 이 프로젝트에서 사용하는 주변장치 주소

주변장치버스Base AddressCMSIS define 근거
USART1APB20x40011000USART1_BASE = APB2PERIPH_BASE + 0x1000
SPI2APB10x40003800SPI2_BASE = APB1PERIPH_BASE + 0x3800
I2C1APB10x40005400I2C1_BASE = APB1PERIPH_BASE + 0x5400

근거 파일: Drivers/CMSIS/Device/ST/STM32F4xx/Include/stm32f446xx.h. Reference Manual의 Memory Map 표와도 교차 확인한다.

4-3. C 코드에서 주변장치 레지스터가 표현되는 방식

/* CMSIS device header의 개념적 구조 */
#define USART1_BASE (APB2PERIPH_BASE + 0x1000UL)
#define USART1 ((USART_TypeDef *) USART1_BASE)

/* HAL 코드에서 */
huart1.Instance->CR1
huart1.Instance->BRR

/* USART1을 선택했다면 각각 USART1 CR1, BRR 레지스터 접근 */

USART1은 단순한 문자열이 아니라 Base Address를 USART 레지스터 구조체 포인터로 형변환한 매크로. 따라서 huart1.Instance->CR1은 USART1의 CR1 메모리 맵 레지스터를 가리킨다.

중요한 차이: huart1.Init.BaudRate는 RAM에 있는 HAL 설정 구조체 필드다. 이것 자체가 하드웨어 BRR 주소는 아님. HAL_UART_Init() 내부에서 이 값을 계산·변환한 뒤 huart1.Instance->BRR에 기록한다.

HSI 16 MHz를 PLL 입력으로 사용한다. PLLM=16, PLLN=336, PLLP=4이므로 SYSCLK은 84 MHz가 된다. AHB는 84 MHz, APB1은 42 MHz, APB2는 84 MHz다.

이 값은 통신 속도 설정의 기반이다. USART1은 APB2 클럭, SPI2와 I2C1은 APB1 클럭을 사용한다. I2C HAL은 PCLK1을 읽어 CR2/CCR/TRISE 설정값을 계산한다.

5-4. main loop의 현재 동작

while (1)
{
    if (BspButtonState == BUTTON_PRESSED)
    {
        BspButtonState = BUTTON_RELEASED;
        BSP_LED_Toggle(LED2);
    }
}

현재 반복문은 버튼 인터럽트 콜백에서 바뀐 상태를 확인하고 LED를 토글한다. UART/SPI/I2C 송수신 함수는 호출하지 않는다.

5-5. main.c에서 가능한 프로그램 흐름 대안

  • Polling: while loop에서 상태 플래그를 계속 확인하고 송수신한다.
  • Interrupt: HAL_UART_Receive_IT(), HAL_SPI_TransmitReceive_IT(), HAL_I2C_Master_Transmit_IT() 등으로 인터럽트 기반 전송을 요청한다.
  • DMA: 각 주변장치의 DMA API를 사용해 메모리와 주변장치 사이 데이터 이동을 DMA가 처리하게 한다.
  • Callback: 전송/수신 완료 또는 오류 콜백에서 후속 처리를 한다.

위 대안은 HAL에서 제공하는 일반적인 구현 선택지이며, 현재 프로젝트에 구현되어 있다는 뜻은 아니다.

6-3. HAL Driver가 실제로 기록하는 코드

파일: Drivers/STM32F4xx_HAL_Driver/Src/stm32f4xx_hal_uart.c

/* HAL_UART_Init() 내부 흐름 */
HAL_UART_MspInit(huart);
__HAL_UART_DISABLE(huart);
UART_SetConfig(huart);
CLEAR_BIT(huart->Instance->CR2, ...);
CLEAR_BIT(huart->Instance->CR3, ...);
__HAL_UART_ENABLE(huart);

핵심 함수인 UART_SetConfig()는 다음처럼 레지스터 필드를 직접 수정한다.

/* Stop bit → CR2 */
MODIFY_REG(huart->Instance->CR2,
           USART_CR2_STOP, huart->Init.StopBits);

/* Word length, parity, TX/RX, oversampling → CR1 */
tmpreg = huart->Init.WordLength
       | huart->Init.Parity
       | huart->Init.Mode
       | huart->Init.OverSampling;

MODIFY_REG(huart->Instance->CR1,
           USART_CR1_M | USART_CR1_PCE | USART_CR1_PS |
           USART_CR1_TE | USART_CR1_RE | USART_CR1_OVER8,
           tmpreg);

/* Flow control → CR3 */
MODIFY_REG(huart->Instance->CR3,
           USART_CR3_RTSE | USART_CR3_CTSE,
           huart->Init.HwFlowCtl);

/* Baud rate → BRR */
huart->Instance->BRR = UART_BRR_SAMPLING16(pclk,
                                           huart->Init.BaudRate);
해석: huart->Instance는 USART1을 가리키므로 huart->Instance->CR1은 USART1 CR1이다. HAL이 설정 구조체의 값을 CR1/CR2/CR3/BRR의 해당 비트 필드로 변환해 기록한다.

           I2C_CR2_FREQ, freqrange);

           I2C_TRISE_TRISE,

9-3. RCC 클럭 활성화는 왜 필요한가?

주변장치와 GPIO 포트는 클럭이 공급되어야 동작한다. 예를 들어 USART1 초기화에는 USART1 peripheral clock과 GPIOA clock을 켜는 코드가 있다.

__HAL_RCC_USART1_CLK_ENABLE();
__HAL_RCC_GPIOA_CLK_ENABLE();

__HAL_RCC_SPI2_CLK_ENABLE();
__HAL_RCC_GPIOB_CLK_ENABLE();
__HAL_RCC_GPIOC_CLK_ENABLE();

__HAL_RCC_I2C1_CLK_ENABLE();
__HAL_RCC_GPIOB_CLK_ENABLE();

이 매크로들은 RCC의 해당 enable bit를 설정한다. USART1은 APB2, SPI2/I2C1은 APB1, GPIOA/B/C는 AHB1 계열 클럭 enable 제어를 사용한다.

9-4. GPIO 핀 주소와 통신 주변장치 주소는 다르다

USART1 Base Address는 USART 내부 레지스터 블록의 시작 주소다. PA9/PA10은 GPIOA 레지스터에서 모드와 AF를 설정하는 핀이다. 즉, 통신 레지스터 주소와 핀 설정 레지스터 주소는 서로 다른 주소 공간의 주변장치 블록이다.

보고서 결론

STM32CubeMX에서 NUCLEO-F446RE 보드를 대상으로 USART1, SPI2, I2C1을 설정하고 코드를 생성하였다. 생성된 프로젝트는 main.c에서 각 주변장치 초기화 함수를 호출하며, 주변장치별 C/H 파일은 HAL 핸들과 초기화 파라미터를 관리한다. 각 HAL 초기화 함수는 MSP 초기화를 통해 GPIO Alternate Function과 주변장치 클럭을 설정한 뒤, HAL Driver 내부에서 설정 구조체의 값을 해당 주변장치의 제어 레지스터에 반영한다.

USART1은 APB2의 Base Address 0x40011000을 사용하며 CR1, CR2, CR3, BRR 등을 통해 송수신 모드와 프레임 및 Baud Rate를 설정한다. SPI2는 APB1의 0x40003800에서 CR1/CR2를 통해 Master 모드, Clock polarity/phase, 분주 및 데이터 형식을 설정한다. I2C1은 APB1의 0x40005400에서 CR1, CR2, OAR1/2, CCR, TRISE 등을 통해 주소 및 Clock timing을 설정한다.

따라서 세 프로토콜은 각각 다른 주변장치 레지스터 블록과 GPIO Alternate Function 핀을 통해 동작한다. 다만 현재 생성 코드는 주변장치 초기화 단계이며 실제 데이터 송수신은 별도의 HAL 전송 API 또는 레지스터 직접 접근 코드를 추가해야 한다.
